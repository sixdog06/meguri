# Meguri（巡る）

对话式的动画圣地巡礼行程规划工具。用户用中文描述想巡礼的作品和目的地，系统检索 anitabi.cn 的真实圣地数据，规划按天组织的行程，每站附对照截图、到达时刻和讲解。

设计原则：大模型只负责理解用户意图和生成文案；地点、距离、时刻等可验证的事实全部由确定性代码和真实数据源产生，不经过模型。

![对话 + 行程面板 + 地图](docs/screenshots/app-overview.png)

以"我想去轻音少女的京都巡礼，三天"为例：

- 第一季、第二季的 124 处圣地合并规划为一个行程，每站保留出处作品标记
- 剧场版的 51 处在欧洲，超出"京都"范围，会在回复正文中说明本次未包含、可另行规划
- 地图按天上色标点并绘制当天路线；每站附截图、到达时刻、讲解和来源署名链接（anitabi 数据为 CC BY-NC-SA，署名是协议要求）
- 行程可编辑（增删站点、换序、换天），编辑后自动重算交通和时刻
- 支持导出 PDF；每天的路线可直接在 Google 地图打开

## 快速开始

需要 Docker 和一个 OpenAI 兼容的 LLM API key（默认使用 kimi）：

```bash
cp .env.example .env.local   # 填入 MEGURI_OPENAI_API_KEY
./start.sh                   # 构建并启动 db + backend + web
```

访问 http://localhost:8080。

首次启动后需要灌入作品目录（Bangumi 全量动画索引，19144 条，作品名解析的数据源）：

```bash
docker compose exec backend python -m app.ingest_works
```

未配置 key 时服务可以正常启动，但对话请求会返回"模型服务暂时不可用"。

## 工作原理

### Agent 循环

编排核心是一个自研的最小 ReAct 循环：

1. 用户消息先落库，SSE 推送 `received` 事件
2. 组装上下文：system prompt（角色、工具清单、输出格式约定）+ 该会话的全部历史
3. 调用 LLM。输出按首字符分类：`{` 开头视为工具调用（缓冲，不上屏），否则视为最终回复（逐段 SSE 流式上屏）
4. 工具调用执行后，观察结果以 `[工具观察结果]` 前缀回灌上下文，进入下一轮；循环上限 5 轮
5. 最终回复落库，行程快照追加到 `itineraries` 表，SSE 推送 `done` 事件

### 工具契约

模型可调用两个工具。

`search_seichi` — 圣地检索。

输入：

```json
{"type": "tool_call", "name": "search_seichi",
 "args": {"ani_name": "轻音少女", "area": "京都"}}
```

输出（返回模型的观察值，同时作为结构化 payload 透传给前端）：

```json
{
  "candidates": [{"id": "abc123", "name": "豊郷小学校旧校舎群", "work": "轻音少女",
                  "area": "滋賀県", "lat": 35.20, "lng": 136.22,
                  "image": "https://...", "ep": 4, "ep_seconds": 812,
                  "origin": "Anitabi@卜卜口", "origin_url": "https://anitabi.cn/"}],
  "by_work": {"轻音少女": 48, "轻音少女 第二季": 76},
  "out_of_area": [{"work": "轻音少女 剧场版", "city": "欧洲", "count": 51}],
  "note": "out_of_area 里的作品在本次地区之外有巡礼点，请在回复中告知用户"
}
```

处理链路：`ani_name` → `anime_works` 表解析出 subjectID（子串精确匹配优先，pg_trgm 相似度兜底错字；多个作品命中时全部返回）→ 逐作品调用 anitabi 获取地标（失败时回退本地离线包并在响应中注明）→ 地区过滤后合并。

`plan_itinerary` — 行程规划。

输入：

```json
{"type": "tool_call", "name": "plan_itinerary",
 "args": {"ani_name": "轻音少女", "area": "京都", "days": 3}}
```

输出（行程快照，落库并随响应返回前端）：

```json
{
  "work": "轻音少女", "area": "京都", "day_count": 3,
  "days": [{
    "day": 1,
    "seichi": [{"id": "abc123", "name": "...", "lat": 35.01, "lng": 135.76, "work": "轻音少女"}],
    "legs": [{"from_id": "abc123", "to_id": "def456", "mode": "transit",
              "duration_minutes": 22, "estimate": false, "degraded": false}],
    "checks": [{"seichi_id": "abc123", "arrive_time": "09:00"}],
    "narrations": [{"seichi_id": "abc123", "text": "《轻音少女》取景地「…」，出自第 4 集…",
                    "citation": {"source": "Anitabi@卜卜口", "url": "https://anitabi.cn/"}}]
  }]
}
```

处理链路：k-means 地理聚类切分天数 → 天内最近邻排序 → 用 OTP（本地 OpenTripPlanner 服务）的真实交通数据替换估算路段 → 推算各站到达时刻 → 根据站点元数据生成讲解。整条链路是确定性代码，地点、距离、时刻等事实不经过模型。

### 作品名解析

用户输入的作品名不一定是标准全名，解析分两步：先在 `anime_works` 表做子串精确匹配；无命中时用 pg_trgm 做相似度匹配。pg_trgm 把字符串切成连续三字符窗口（trigram）的集合，相似度取共有 trigram 的占比——错一个字只影响相邻几个窗口，因此错字仍能命中（"吹响吧上低音号" 少个标点也能解析到 115908）；而"京吹"与"吹响吧！上低音号"没有公共 trigram，如实不命中（简称归一化由上游 LLM 负责）。该方案不依赖分词，中日文混排天然适用；GIN 倒排索引保证查询不扫全表。

### 故障语义

外部数据源的状态对用户显式可见，区分三种情况：anitabi 故障且本地有离线包 → 降级使用离线数据包并提示"可能不是最新"；故障且无离线包 → 503 "圣地数据服务暂时不可用"；服务正常但该作品无数据 → 200 + "这部作品没有圣地巡礼数据"。系统可以降级，但不静默用旧数据冒充实时数据。

### 评测

评测是带标准答案的 golden 数据集，在假外部环境（脚本化 LLM、内存假数据）中运行完整的真实管线，再用确定性规则打分。与后端行为测试分离，需显式运行：

```bash
.venv/bin/python -m pytest eval/ -v -s   # 需要 5433 端口的 Postgres（compose db）
```

各维度的输入、输出与打分算法：

- **Scout 检索命中率**。输入：作品名 + 地区 + 假仓库材料（含区域外干扰项）。输出：候选圣地 id 列表。算法：命中率 = 期望 id 与实际 id 的交集大小 ÷ 期望集大小；期望为空时实际也必须为空。
- **Planner 切天质量**。输入：候选圣地列表 + 天数。输出：按天组织的行程快照。算法：天数等于请求天数、每天至少一站、候选点全覆盖、最近邻排序的总距离不劣于固定种子随机基线（打乱 20 次取平均），四条全真才通过。
- **Navigator 时间可行性**。输入：候选圣地 + 天数 + 假交通数据。输出：各站计划到达时刻。算法：每站有时刻记录、时刻为 HH:MM 格式、天内时刻单调不倒流。
- **Storyteller 讲解接地**。输入：带来源字段的候选圣地。输出：各站讲解文本与 citation。算法：讲解文本必须出现本站站名，且 citation 的来源署名必须等于该站的 origin 字段。
- **e2e 端到端清单**。输入：一条自然语言消息和全套假环境。输出：完整请求的响应、落库数据与 trace 文件。算法：六项谓词全部通过——有回复、天数正确、有交通段、有时刻、讲解带署名、trace 四类埋点齐全。
- **work_resolve 作品名解析**。输入：作品名查询词（唯一打真实数据库的维度，测试库灌入 19144 条真实 Bangumi 索引）。输出：解析出的作品 subjectID 列表。算法：8 个 case 全部通过——官方全名（"轻音少女"命中三部曲且第一季居首）、具体季、带空白、日文原名、错字救回、俗名如实不命中、未收录返回空、歧义取最短名。这组 case 同时用于标定 pg_trgm 的相似度阈值。
